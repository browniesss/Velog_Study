<h4 id="아이템-11-net-리소스-관리에-대한-이해">아이템 11: .NET 리소스 관리에 대한 이해</h4>
<p>.NET Framework를 사용 시 가비지 컬렉터가 메모리 관리를 대부분 잘 해주기에, 개발자가 보통은 크게 신경을 쓰지 않아도된다.</p>
<ul>
<li>마크/컴팩트(Mark/Compact) 알고리즘을 통해 객체 사이의 연관 관계를 효율적으로 파악하여 더 이상 사용되지 않는 객체를 자동으로 제거함<ul>
<li>마크/컴팩트 알고리즘이란 ?<ul>
<li>Mark and Sweep(이하 MAS) 알고리즘에서 Compact 단계가 추가된 가비지 컬렉팅 알고리즘으로, 루트 객체에서 타고 내려가면서 참조하지 못하는 객체들을 단순 해제시키는 기존 MAS 알고리즘의 문제인 메모리 단편화(Memory Fragmentation)을 해결하기 위해 MAS 알고리즘에비어있는 공간을 압축시키는 Compact 단계가 추가된 알고리즘이다.</li>
</ul>
</li>
</ul>
</li>
</ul>

<p>이처럼 관리 힙에 대한 메모리 관리는 가비지 컬렉터가 해주지만, 그 외 비관리 리소스는 여전히 개발자가 관리해야 한다. 그렇기에 .NET Framework에서는 개발자가 손쉽게 비관리 리소스를 관리할 수 있도록 2가지 메커니즘을 제공한다.</p>
<ul>
<li>finalizer<ul>
<li>비관리 리소스에 대한 해제 작업이 반드시 수행될 수 있도록 도와주는 방어적인 메커니즘</li>
<li>단점이 많기에, IDisposable 인터페이스를 사용하는게 좋음.<ul>
<li>언젠가는 가비지 컬렉팅이 될거지만, 언제 호출될지는 아무도 모름</li>
</ul>
</li>
</ul>
</li>
<li>IDisposable 인터페이스<ul>
<li>아이템 17에서 이어서 진행</li>
</ul>
</li>
</ul>
<hr />
<p>finalizer를 사용하면 안되는 이유
finalizer를 사용하면, 성능이 나빠진다. finalizer를 가지고 있는 객체가 가비지 컬렉팅 대상에서 바로 지워지지 않기 때문, 왜냐하면 finalizer를 호출해야하기 때문인데 가비지 수집을 수행하는 스레드에서 직접 finalizer를 호출할 수 없고, 이 객체에 대한 참조를 다른 큐에 넣어두고 나중에 finalizer가 호출될 수 있도록 사전 준비만을 수행한다.</p>
<p>위처럼 간단하게만 봐도 성능이 안좋아질 것 같은데, 가비지 컬렉팅을 할 때 세대(Generation) 개념이 존재하는데 처음 가비지 컬렉팅 대상이 될 경우 0세대, 가비지 컬렉팅 대상에서 살아남았다면 1세대로 이동, 이후에도 살아남았다면 2세대로 이동.. 이런식으로 동작한다.</p>
<p>0세대의 경우 매번 가비지 컬렉팅 대상이 되지만, 1, 2세대는 0세대가 10번돌 때 1세대가 1번, 1세대가 10번 돌 때 2세대가 1번(즉, 0세대 100번에 2세대 1번 꼴) 정도 가비지 컬렉팅 대상이 되는데, finalizer가 있는 객체는 처음 컬렉팅 대상이 될 때 무조건 살아남기에 1세대로 이동하고, 그 이후에도 만약 살아남는다면 2세대로 이동하여 가비지 컬렉팅이 완료될 때 까지 메모리를 차지하기에 성능에 안좋은 영향을 끼치는 것이다.</p>
<p>이러한 단점을 해결하기 위해 IDisposable 인터페이스와 표쥰 Dispose 패턴을 활용해야 한다.</p>
