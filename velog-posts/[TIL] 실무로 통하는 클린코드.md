<h1 id="빈약한-모델">빈약한 모델</h1>
<h2 id="객체-설계의-핵심-원칙">객체 설계의 핵심 원칙</h2>
<p><strong>속성 보호와 동작 중심 설계</strong>
객체의 모든 속성을 private으로 설정하고 의미 있는 동작만 노출해야 합니다. 이는 외부 조작으로부터 객체를 보호하고 더 나은 캡슐화를 제공합니다.</p>
<p><strong>Setter 제거</strong>
세터 메서드는 객체의 불변성을 해치므로, 필수 속성은 생성자를 통해 초기화하고 세터를 제거해야 합니다. &quot;묻지 말고 말하라(Tell, Don't Ask)&quot; 원칙을 따라 객체에게 직접 행동을 요청하는 방식으로 설계합니다.</p>
<p><strong>Getter 최소화</strong>
게터 메서드를 통한 직접적인 데이터 접근을 지양하고, 객체의 행동을 표현하는 명시적인 메서드를 제공해야 합니다. 이는 데메테르의 법칙을 준수하고 객체 간의 결합도를 낮추는데 도움이 됩니다.</p>
<h2 id="실전-적용-방안">실전 적용 방안</h2>
<p><strong>DTO 사용 최소화</strong>
데이터 전송만을 위한 DTO 대신 실제 비즈니스 로직을 포함한 도메인 객체를 사용하면 코드 중복을 줄이고 시스템의 복잡성을 낮출 수 있습니다.</p>
<p><strong>완전한 객체 생성</strong>
빈 생성자 사용을 피하고, 객체 생성 시점에 모든 필수 속성을 초기화하여 일관성 있고 예측 가능한 객체를 만들어야 합니다.</p>
<p><strong>동적 속성 제거</strong>
명시적으로 속성을 선언하여 코드의 안정성을 높이고 디버깅을 용이하게 만듭니다. 동적 속성은 런타임 오류와 명명 충돌의 위험이 있으므로 피해야 합니다.</p>
<p>이러한 원칙들을 적용하면 더 견고하고 유지보수가 용이한 객체 지향 시스템을 구축할 수 있습니다.</p>
