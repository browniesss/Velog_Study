<h1 id="chapter-6-선언적-코드">Chapter 6. 선언적 코드</h1>
<blockquote>
<p><strong>&quot;소프트웨어에서 가장 중요한 것은 동작입니다. 사용자는 동작에 의존합니다.<br />만약 사용자가 원하는 동작을 추가하면(사용자가 진정으로 원하는 것이라면) 좋아하지만,<br />의존하는 동작을 변경하거나 제거하면(버그가 발생하면) 더 이상 신뢰하지 않습니다.&quot;</strong><br />— 마이클 페더스</p>
</blockquote>
<p>소프트웨어는 사용자가 기대하는 동작을 일관되게 제공해야 하며, 이를 위해 코드를 <strong>선언적</strong>으로 작성하는 것이 중요합니다. 아래는 선언적 코드 작성을 위한 핵심 원칙들을 정리한 내용입니다.</p>
<hr />
<h2 id="1-변수와-책임-관리">1. 변수와 책임 관리</h2>
<ul>
<li><p><strong>변수 범위 최소화:</strong><br />한 변수를 여러 목적에 재사용하지 말고, 각 역할에 맞는 변수를 별도로 선언하세요.<br /><em>예시:</em> 합계와 총 지불 금액 계산 시 같은 <code>total</code> 변수 대신, <code>lineTotal</code>, <code>amountTotal</code>과 같이 의도를 드러내는 이름 사용.</p>
</li>
<li><p><strong>책임의 적절한 분리:</strong><br />각 클래스나 객체는 자신의 역할에 맞는 책임만 가지도록 하세요.<br />예를 들어, 그래픽 편집기에서 수학적 상수(PI)를 관리하는 것은 적절하지 않으며, 관련 상수는 전용 객체(예: <code>RealConstants</code>)에 정의하는 것이 좋습니다.</p>
</li>
</ul>
<hr />
<h2 id="2-코드-구조와-가독성">2. 코드 구조와 가독성</h2>
<ul>
<li><p><strong>빈 줄 대신 함수 분리:</strong><br />빈 줄을 통해 코드 블록을 나누는 대신, 기능별로 작은 함수로 분리하여 KISS 원칙을 따르세요.<br /><em>예시:</em> 파일 처리 작업을 하나의 긴 함수로 작성하기보다는, 읽기, 변환, 저장 등을 별도의 함수로 분리.</p>
</li>
<li><p><strong>명시적 반복문 사용:</strong><br />인덱스 기반 반복은 캡슐화를 깨뜨릴 수 있으므로, 가능하다면 <code>foreach</code>나 고차 함수(예: <code>map</code>, <code>filter</code>)를 사용해 선언적으로 처리하세요.</p>
</li>
</ul>
<hr />
<h2 id="3-이름-짓기와-의도-표현">3. 이름 짓기와 의도 표현</h2>
<ul>
<li><p><strong>긍정적 이름 사용:</strong><br />변수, 메서드, 클래스 이름은 이중 부정을 피하고 긍정적인 표현을 사용하여, 코드를 읽는 사람이 의도를 쉽게 파악할 수 있도록 해야 합니다.<br /><em>예시:</em> <code>if (!work.isNotFinished())</code> 보다는 <code>if (work.isDone())</code>가 명확합니다.</p>
</li>
<li><p><strong>매직 넘버 제거:</strong><br />코드 내에 의미 없는 숫자나 값(매직 넘버)은 상수로 정의해, 그 의미를 드러내야 합니다.</p>
</li>
</ul>
<hr />
<h2 id="4-함수와-메서드-관리">4. 함수와 메서드 관리</h2>
<ul>
<li><p><strong>버전 정보 포함 금지:</strong><br />함수 이름에 <code>_new</code>, <code>_old</code> 등 버전 정보를 넣으면 혼란을 초래합니다. 하나의 최신 버전만 유지하고, 버전 관리 시스템에 기록하세요.</p>
</li>
<li><p><strong>설계 결정은 코드로 표현:</strong><br />주석에 의존하기보다는, 함수명이나 구조를 통해 설계 의도를 명확히 드러내야 합니다.<br /><em>예시:</em> <code>increase_memory_to_avoid_false_positives()</code>와 같이, 함수 이름만 보고도 목적을 이해할 수 있도록 작성.</p>
</li>
</ul>
<hr />
<h2 id="5-오류-처리와-비동기-코드">5. 오류 처리와 비동기 코드</h2>
<ul>
<li><p><strong>명확한 오류 메시지:</strong><br />오류가 발생했을 때, 사용자가 이해할 수 있도록 구체적이고 선언적인 오류 메시지를 제공하세요.</p>
</li>
<li><p><strong>콜백 지옥 피하기:</strong><br />중첩된 콜백 대신, Promise나 async/await와 같은 최신 비동기 처리 방식을 활용해 가독성 높은 코드를 작성하세요.</p>
</li>
</ul>
<hr />
<h2 id="6-타입과-변환">6. 타입과 변환</h2>
<ul>
<li><strong>암묵적 변환 제거:</strong><br />서로 다른 자료형 간의 연산이나 암묵적 변환으로 인한 모호함을 피하고, 항상 명시적으로 변환하여 예측 가능한 코드를 작성해야 합니다.</li>
</ul>
<hr />
<p>이와 같은 원칙들을 따르면, 코드가 보다 선언적이고 의도가 명확해져 유지보수 및 확장이 쉬워집니다.<br />코드의 각 요소가 <strong>무엇</strong>을 하는지와 <strong>어떻게</strong> 하는지를 명확히 구분해 표현하는 것이 핵심입니다.</p>
