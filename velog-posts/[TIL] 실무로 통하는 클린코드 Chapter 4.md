<h2 id="기본형-집착">기본형 집착</h2>
<blockquote>
<p>기본형 타입에 대한 강박관념은 기본형 집착입니다.
리치 하키 (Rich Hickey) </p>
</blockquote>
<h2 id="기본형-집착의-문제점">기본형 집착의 문제점</h2>
<p>기본형 타입(int, string 등)을 과도하게 사용하면 코드가 장황해지고 유지보수가 어려워집니다. 이는 데이터의 의미와 책임이 명확하게 표현되지 않기 때문입니다. 예를 들어, 단순히 문자열로 이메일 주소를 표현하면 유효성 검사나 관련 동작을 매번 구현해야 하는 번거로움이 있습니다.</p>
<h2 id="해결-방안">해결 방안</h2>
<p><strong>작은 객체 생성</strong></p>
<ul>
<li>기본형 대신 구체적인 클래스를 만들어 사용합니다</li>
<li>각 객체가 명확한 책임을 가지도록 설계합니다</li>
<li>데이터 유효성 검사를 객체 내부에서 처리합니다</li>
</ul>
<p>예를 들어, Person 클래스에서 name을 단순 문자열로 저장하는 대신 Name 클래스를 만들어 이름에 대한 유효성 검사와 관련 동작을 캡슐화할 수 있습니다.</p>
<p><strong>문자열 남용 제거</strong></p>
<ul>
<li>정규식이나 문자열 분리 대신 객체를 활용합니다</li>
<li>추상화를 통한 기능 확장이 용이해집니다</li>
<li>재사용성과 테스트가 쉬워집니다</li>
</ul>
<p>예를 들어, 학교 정보를 다룰 때 문자열 파싱 대신 School과 Location 객체를 만들어 의미있는 객체 간의 상호작용으로 문제를 해결할 수 있습니다.</p>
<p><strong>불필요한 속성 제거</strong></p>
<ul>
<li>YAGNI(You Aren't Gonna Need It) 원칙을 준수합니다</li>
<li>실제 필요한 동작을 중심으로 설계합니다</li>
<li>코드의 단순성과 직관성이 향상됩니다</li>
</ul>
<h2 id="실제-적용-사례">실제 적용 사례</h2>
<p><strong>이메일 주소 처리</strong>
단순히 문자열로 저장하는 대신 EmailAddress 클래스를 만들어 유효성 검사와 관련 기능을 캡슐화합니다. 이를 통해 이메일 관련 로직이 한 곳에서 관리되며, 재사용성과 유지보수성이 향상됩니다.</p>
<p><strong>날짜 구간 처리</strong>
시작일과 종료일을 별도의 DateTime으로 관리하는 대신 Interval 클래스를 만들어 날짜 구간에 대한 유효성 검사와 계산 로직을 포함시킵니다. 이로써 잘못된 날짜 입력을 방지하고 관련 기능을 쉽게 확장할 수 있습니다.</p>
<p><strong>지리적 좌표 처리</strong>
위도와 경도를 단순 숫자로 저장하는 대신 GeographicCoordinate 클래스를 만들어 좌표의 유효성을 검사하고 거리 계산 등의 기능을 추가할 수 있습니다.</p>
<h2 id="결론">결론</h2>
<p>기본형 타입에 대한 집착에서 벗어나 적절한 객체 설계를 통해 코드의 품질을 높일 수 있습니다. 이는 단순히 코드를 객체로 감싸는 것이 아니라, 해당 데이터와 관련된 책임을 명확히 하고 캡슐화하는 과정입니다. 이를 통해 코드의 재사용성, 유지보수성, 테스트 용이성이 크게 향상됩니다.</p>
